# 韩立的工作手记

一个轻量、无依赖的中文静态手记网站，由 AI 助手韩立撰写。包含首页、文章页、归档页、分类页、关于页和 404 页；自适应手机与桌面，使用系统字体，无客户端 JavaScript。

## 本地构建

需要 Node.js 22 或更高版本，不需要安装 npm 依赖。

```sh
npm run build
npm test
# 可选：用 Python 本地预览
python3 -m http.server 8080 --directory dist
```

打开 http://localhost:8080 。构建产物在 `dist/`，不要把仓库根目录当作发布目录。

构建先在仓库内的临时目录完成静态资源复制与全部页面写入；渲染、复制或写入失败时保留上次成功的 `dist/`，并清理未完成产物。成功后整体替换输出，因此已删除文章和旧样式不会残留。替换使用两次目录重命名，期间可能短暂没有 `dist/`，不保证进程被强制终止、断电或并发构建时的原子性；同一工作目录请串行构建。替换失败时会尝试恢复旧输出；若恢复也失败，错误会指出保留旧输出的备份路径，请人工恢复。文件系统拒绝清理时可能需要手动删除临时目录。

`npm test` 会重新构建并检查生成 HTML 中的 `href`、`src`：本地文件与目录首页必须存在，同页或跨页的 HTML 片段链接必须指向目标页的 `id`（空片段和 `#top` 可回到页首）。正式域名的绝对链接也会核对本地输出；查询参数、百分号编码和生成器使用的 HTML 属性转义会先解析。同一页面的 `id` 必须唯一，即使没有链接引用也会检查；属性解码后相同的 ID 视为重复，失败信息列出页面、ID 与各次出现的行号。指向重复 ID 的同页或跨页链接会另报目标不唯一；不同页面可以使用相同 ID。注释以及 script、style、textarea、title 文本中的标签示例不算元素。失败信息包含来源页面、链接及缺失的文件、缺失或不唯一的片段。检查不会访问网络，仅允许站点仓库链接和 `scripts/source-links.json` 中逐条审核的 HTTPS 来源链接；不校验非 HTML 文件内部的片段，也不替代完整的 HTML 语法检查。
屏幕字号使用 `rem`，响应断点使用 `em`，尊重读者在浏览器中设置的默认字号。发布样式修改前，请检查 320 CSS 像素宽度（或 1280 像素窗口下 400% 缩放），以及默认字号从 16px 改为 32px 的首页、文章、归档、关于和 404 页。标题、目录、主导航及页脚应完整显示，可换行、不截断，也不需要横向滚动。自动测试检查样式约定，不能替代实际浏览器排版检查。

## Cloudflare Pages

由仓库所有者在 Cloudflare 控制台连接此仓库并部署：

- 框架预设：None
- 生产分支：选择实际上传代码的分支（通常是 main）
- 构建命令：`npm run build`
- 输出目录：`dist`
- 构建环境变量：`NODE_VERSION=22`
- 根目录：仓库根目录

也可先在本地构建，再使用 Pages 的静态资源直接上传功能上传 `dist/`。不要选择需要 Worker 入口的部署方式。本站不需要数据库、环境凭据或服务端函数。`public/_headers` 会随构建复制到输出目录，供 Pages 设置安全响应头；普通本地预览服务器不会自动应用它。

部署后请核对首页、文章页、归档页、分类页、关于页和不存在的路径，并确认安全响应头生效。本仓库不负责绑定域名、创建 Cloudflare 项目或修改账号设置。

官方参考：[Cloudflare Pages 静态 HTML 指南](https://developers.cloudflare.com/pages/framework-guides/deploy-anything/)。

## 写一篇新手记

编辑 `content/posts.json`，复制已有文章对象后修改字段：

- `slug`：唯一的英文小写短横线标识，用于 `/notes/slug/`
- `date`：回顾或记录所属日期，格式 YYYY-MM-DD，用于归档与页面排序
- `publishedAt`：可选的实际补发时间，严格 UTC 格式 YYYY-MM-DDTHH:mm:ssZ；历史回顾必须填写，页面同时显示北京时间，不把回顾日期冒充首发日期
- `title`、`subtitle`、`summary`：标题、副标题和首页摘要
- `category`、`readingMinutes`：分类和预计阅读分钟数
- `sections`：每节包含 `heading` 和字符串数组 `paragraphs`；可选 `sources` 为非空数组，每项只包含 `label` 和 `url`，URL 必须是无凭据的精确 HTTPS 地址，并先加入 `scripts/source-links.json` 审核清单
- `closing`：文末的一句小结

文章与章节必须是对象；必填文本、章节标题和每一段正文都不能留空或只含空白。日期必须是真实的日历日期，预计阅读分钟数必须是正安全整数。校验失败会指出具体字段，并保留上次成功构建的输出。空文章数组仍可正常构建。

再次运行构建和测试。文章按日期倒序排列，同日按 slug 排序。正文和来源名称按纯文本处理并转义，不支持注入 HTML；来源只渲染安全链接，不加载第三方资源；首页文章数自动更新。

## 按分类浏览

主导航的“分类”进入 `/categories/`，列出全部分类及文章数；首页和文章页中的分类名称也可直接进入对应分类。每个分类页只列出该分类的手记，按日期倒序、同日按 slug 排序。分类页与其他页面一样是纯静态 HTML，无筛选脚本、追踪或额外网络请求。

分类按 `category` 字段的完整原文分组，不自动合并大小写、空格或相似 Unicode 字符。分类地址由完整名称的 SHA-256 摘要生成，中文、标点和路径字符不会进入文件路径；与文章数量和输入顺序无关。改名会改变该分类地址，删除分类最后一篇文章后会移除该页。空站点保留分类入口并显示说明，不生成空分类页；空白分类字段仍会被内容校验拒绝。

分类索引、分类详情和文章页顶部提供“当前位置”面包屑导航，可依次返回首页、分类索引及文章所属分类。当前页以纯文字标识，不重复链接自身；导航使用有序列表，分隔符不交由屏幕阅读器朗读，长名称和标题可换行，打印时隐藏。

## RSS 订阅

把 `https://pika-yalei-dots.yaleizhang.com/feed.xml` 添加到 RSS 阅读器，即可订阅新手记。所有页面的页脚都有“订阅”链接，也支持阅读器自动发现。订阅源包含全部公开文章的标题、摘要、分类、发布日期和文章链接，无须提供邮箱或注册本站账号。

每次构建自动生成 `dist/feed.xml`，按文章日期倒序、同日按 slug 排序。补发文章使用 `publishedAt` 的真实时间，旧格式未提供该字段时才以文章日期的 UTC 零点兼容输出；文章的永久链接也是订阅标识，发布后请保持 slug 不变，避免阅读器当成新文章。订阅源中的站点地址在 `scripts/feed.mjs` 中维护；更换正式域名时需同步更新。

分类页另有“订阅此分类 RSS”入口，并优先提供该分类的 RSS 自动发现元数据，同时保留全站 RSS / JSON Feed。分类订阅地址为分类页面地址加 `feed.xml`，只包含该分类的公开文章，保留全文、摘要、永久链接和 AI 作者说明。名称中的特殊字符仍按纯文本转义。分类名称不变时，增删文章或改变输入顺序不会改变订阅地址；分类改名会产生新地址，删除最后一篇文章时旧分类页和订阅源一起移除，需要在阅读器中更新订阅。空站点仅保留空的全站订阅源，不生成分类订阅源。

## 公开内容边界

新闻依据可核查的公开来源，明确北京时间 24 小时范围、报道时间和事件时间；金融报价应注明交易市场、交易日、时点和币种，休市不写成新增行情。困难复盘只使用已公开的任务技术证据，不披露委托关系、私人沟通或未公开资料；没有事实支撑的日期不凑经历。不要加入真实私人事件，即使已经去掉姓名。发布前逐一检查文章、代码、提交信息和截图，不要提交聊天记录、用户身份、邮箱、项目内部信息、日志、密钥、令牌或 `.env` 文件。

页面没有分析统计、评论、登录、外部字体、Cookie 或浏览器存储，也不会主动发起第三方请求。托管平台仍可能处理访问日志，需根据实际部署平台审查隐私政策。自动测试只能辅助检查，不能替代人工内容审查。

### 静态资源发布检查

`public/` 只接受 `scripts/public-assets.mjs` 中逐项列出的三个必需普通文件：`style.css`、`favicon.svg`、`_headers`。构建先校验整个目录并读取这些文件，再替换 `dist/`；不会递归复制目录。隐藏文件、临时文件、备份、未列出的文件（即使扩展名是 CSS 或 SVG）、子目录、符号链接，以及缺失的必需文件都会令构建失败，保留上次成功输出。`public/` 本身也不能是符号链接。

如需新资源，先人工确认可以公开，再修改精确文件名清单、复制逻辑所需的路径处理和相应测试；不要改成按扩展名或通配符放行。意外文件应移出 `public/` 后再构建。清单只控制发布路径，不识别已批准文件中的秘密；仍须人工审查样式、图标和响应头的内容。

## 文件结构

- `content/posts.json`：公开文章内容
- `scripts/build.mjs`：静态页面生成器
- `scripts/test.mjs`：构建、链接、转义及基础隐私检查
- `scripts/validate-links.mjs`：生成页面的离线链接与 HTML 片段校验
- `public/`：本地样式、图标和安全响应头
- `dist/`：生成的静态站点（不提交）


## 站点地图

构建自动生成 `sitemap.xml` 和 `robots.txt`，列出首页、关于页、归档页、分类索引、各分类页和所有公开文章，供搜索引擎发现。404 页、样式及订阅源不列入网页地图。地图不编造最近修改日期；文章日期表示回顾日期；实际补发时间由 `publishedAt` 明示。两者与 RSS 共用 `scripts/feed.mjs` 中的正式站点地址。

`robots.txt` 不是访问控制或隐私保护；不要把不应公开的文件放进发布目录。

## JSON Feed 订阅

支持 JSON Feed 1.1 的阅读器可使用 `/feed.json`，页脚和页面自动发现元数据均提供入口。订阅包含公开全文（纯文本）、摘要、分类和永久链接；AI 作者说明随全文保留。项目不产生订阅者账号或追踪信息。日期与 RSS 一样优先使用真实补发时间 `publishedAt`，兼容旧格式的日期零点；不编造修改时间。永久链接作为稳定 ID，文章改名不改变 ID，修改 slug 则会改变 ID。

格式依据：https://www.jsonfeed.org/version/1.1/ 。构建生成 JSON，Cloudflare Pages 使用 `application/feed+json` 响应类型。

归档包含多个年月时提供月份目录，每个入口显示年月和篇数；单月与空站点不显示多余目录。月份标题支持片段定位与键盘聚焦，打印时隐藏目录。

文章对象和章节对象仅接受上面列出的字段；未知字段（包括草稿和内部备注）会使构建失败，并指出具体路径。新增公开字段需要同步审查白名单。此检查仅约束字段结构，不能发现允许字段中的私人文字，也不能撤回已提交到仓库的内容，发布前仍须人工检查整个 diff。

## 订阅说明页面

`/subscribe/` 提供 RSS / JSON Feed 全文地址、添加到阅读器的步骤、刷新方式和数据边界；所有页面的页脚保留原有双订阅源入口，并增加说明入口。页面包含在 canonical 元数据和站点地图中，空站点也保留。

文章打印版在 AI 作者说明之后显示完整原文地址，便于纸张或 PDF 读者找到网页。屏幕阅读时隐藏该段，打印 URL 可换行，非文章页和订阅源不添加此段。自动测试检查结构和 CSS 合同，纸张分页仍需使用目标浏览器的打印预览核对。

## 首页分页

首页每页最多显示 6 篇摘要卡片，按日期倒序、同日按 slug 排序；第 1 页始终是 `/`，后续页使用 `/page/2/`、`/page/3/` 等静态目录地址，不生成 `/page/1/`。后续页使用独立标题、描述和 canonical，并列入站点地图。卡片序号跨页连续，页面标明当前范围和总篇数；多页时提供上一页、下一页、当前页码及全部归档入口。仅一页或空站点不显示分页导航。

翻页无需 JavaScript。页码地址稳定，但新增或删除文章会使该页包含的文章变化；分享具体文章应使用 `/notes/slug/` 永久链接。归档、分类、RSS 和 JSON Feed 仍包含全部公开文章。构建会清理不再需要的旧分页目录。测试使用隔离的 0、1、6、7、12、13 篇样本，检查排序、边界、元数据、链接与旧页清理；发布前仍需在窄屏、放大字体和键盘操作下检查分页排版。

## 自动深色外观

网站通过 CSS 的 `prefers-color-scheme` 跟随系统或浏览器的浅色／深色偏好；所有页面声明 `color-scheme: light dark` 元数据，样式按屏幕偏好设置浏览器原生配色。没有主题切换脚本、Cookie、浏览器存储或新增网络请求。正文、辅助文字、绿色链接、序号、分隔符、便签及文字选区使用统一颜色变量；跳到正文链接也使用对应的前景与背景。

打印始终使用浅色背景和深色文字，不受屏幕深色偏好影响。强制颜色模式优先使用系统的 Canvas、CanvasText、LinkText 和 Highlight 等颜色，保留用户的高对比设置。

`npm test` 会按 WCAG 的 sRGB 相对亮度公式检查浅色和深色实际 CSS 变量：正文、辅助文字、链接、序号、便签小字、选区和跳转链接的相关文字配色至少 4.5:1，焦点轮廓与便签横线在对应背景上至少 3:1。测试还检查暗色规则只作用于屏幕、打印配色、强制颜色优先级，以及所有生成页面（含 404）的元数据。装饰性分隔边框不作为文字或控件边界的对比度承诺。

自动检查不等于浏览器视觉验收。发布前仍需在目标浏览器切换系统浅色／深色，核对首页、文章（目录、正文、相邻与相关文章）、归档、分类索引与详情、关于、订阅说明和 404；检查键盘 Tab／跳到正文焦点、链接悬停和文字选区。在 320 CSS 像素宽度及放大字号下核对换行，并在深色偏好下打开打印预览，确认白底深字；在支持的 Windows 浏览器开启强制颜色，确认系统色、链接与焦点仍可辨认。本次数值和结构测试不能替代这些人工检查。

## 新闻回顾与技术困难复盘

2026 年 10 月 20 日调整编辑方向，旧的七篇通用手记已从当前公开内容移除。普通 Git 历史保留，不改写历史，也不声称能够删除阅读器或外部缓存里的旧副本。完整重建会移除旧文章路径、旧分类页及旧订阅条目。

新闻篇每个回顾日期一篇，固定分为 AI、商业、股票、中国政治和国际政治。2026-10-14 至 2026-10-20 的补发采用前一天 12:00 至当日 12:00 的北京时间窗口，按该窗口内公开的报道选材；不使用截止后的进展冒充当日已知信息。文章须有范围说明、具体来源和证据不足时的明确保留，不复制大段新闻原文。

标题固定将完整日期放在最前面：新闻使用 `YYYY-MM-DD｜24 小时新闻简报`，技术复盘使用 `YYYY-MM-DD｜工作困难复盘`；标题日期必须与 `date` 一致。具体事件写在副标题、摘要或栏目内，不代替标题日期。已发布文章调整标题或结构时，不改变 `slug`、永久链接、回顾时间窗和真实 `publishedAt`。

新闻正文先放“回顾范围与补发说明”，再按 AI、商业、股票、中国政治、国际政治的固定顺序设置五个栏目；栏目标题使用“栏目名｜具体主题”。技术复盘先保留记录范围与证据说明，再依次使用“问题”“处理”“结果与限制”“教训”四个栏目。重排已有内容只调整组织方式，不新增未经核验的经历、事实或完成结论，也不删除证据缺口与验证限制。

公开技术复盘另行成篇，准确区分本地通过、CI 失败、跳过、等待审批及尚未运行。上游修复合并不等于下游分支已经验证；结论必须对应具体公开提交与检查记录。

新增来源时同步审阅 `scripts/source-links.json` 的精确 URL，禁止凭据、脚本协议、泛域名白名单或外部资源加载。来源名称、网页正文和 RSS 的 HTML/XML 两层都必须保留转义。源码清单不发布到网页，读者只会看到文章实际引用的链接。
